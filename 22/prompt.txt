- **Concurrency isn't the cause.** One Google search follows at most about 10 redirects, and 200 at once went through without a single drop.
- **The real cause of the 418 drops is still unknown.** My best guess is that Google's redirect links only start working a little while after the search that produces them. They failed right after recording and all worked later. Confirming that needs fresh searches, which cost credits, so I haven't tested it.
- **A backoff would be a hand-rolled retry,** and CLAUDE.md bans those unless a broken user path demands it. Nothing measured here does.
- **The worst case is no longer silent.** If every redirect in a search fails, the search now throws, counts as a failed search, and can trigger the outage error. If only some fail, just those pages are lost, which costs the same as a result that never had a link.

If drops ever show up in prod, the fix is the PRD's error handling: Mastra's built-in retry around the search step. That's already in place, and no backoff is needed.
